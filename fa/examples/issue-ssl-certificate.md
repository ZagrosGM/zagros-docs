# صدور گواهی SSL

پنل می‌تواند از طریقِ ACME برای شما گواهی صادر و تمدید کند.

## پیش از شروع

* دامنه باید همین حالا به این سرور اشاره کند.
* **پورتِ ۸۰ باید آزاد و در دسترس باشد** — اعتبارسنجیِ HTTP-01 از آن استفاده
  می‌کند. زاگرس اول پورت را بررسی می‌کند و اگر چیزِ دیگری روی آن باشد می‌گوید.
* یکی از کلاینت‌های پشتیبانی‌شده نصب باشد: `certbot`، `acme.sh` یا `lego`.
  داشبورد نشان می‌دهد کدام را پیدا کرده.

## از داشبورد

1. **Certificates → Issue** را باز کنید.
2. دامنه را بنویسید (مثلاً `panel.example.com`).
3. تأمین‌کننده را انتخاب کنید یا روی حالتِ خودکار بگذارید.
4. منتظرِ اعتبارسنجی بمانید — یک گواهیِ مدیریت‌شده با تاریخِ انقضا در فهرست
   پدیدار می‌شود.

گواهی زیرِ پوشهٔ داده ذخیره می‌شود و **تمدیدِ خودکار** دارد؛ لازم نیست برگردید.

## استفاده برای پنل

```bash
sudo zagros env set TLS_MODE on
sudo zagros env set UVICORN_SSL_CERTFILE /var/lib/zagros/certs/live/panel.example.com/fullchain.pem
sudo zagros env set UVICORN_SSL_KEYFILE  /var/lib/zagros/certs/live/panel.example.com/privkey.pem
sudo zagros restart
sudo zagros status
```

## استفاده برای لینک‌های اشتراک

در **Subscriptions → TLS certificate** آن را انتخاب کنید. این همان چیزی است که
نشانی‌های `https://` را وقتی شنوندهٔ اشتراک اختصاصی است، ممکن می‌کند.

## وقتی صدور شکست می‌خورد

| پیام | رفع |
|---|---|
| پورتِ ۸۰ اشغال است | برای همان یک دقیقه سرویسِ دیگر را متوقف کنید و دوباره تلاش کنید |
| هیچ تأمین‌کنندهٔ ACME پیدا نشد | یکی از `certbot`، `acme.sh` یا `lego` را نصب کنید |
| دامنه resolve نمی‌شود | اول رکوردِ DNS را به این سرور برسانید؛ اعتبارسنجی از اینترنت انجام می‌شود، نه از مرورگرِ شما |

```bash
sudo zagros logs          # خطای خودِ کلاینت همان‌طور منتقل می‌شود
sudo zagros doctor        # پورت‌ها و DNS را بررسی می‌کند
```

::: tip
تمدید یک کارِ زمان‌بندی‌شده است. اگر گواهی به انقضا نزدیک است و تمدید نشده،
`zagros doctor` گزارش می‌دهد — بررسی کنید پورتِ ۸۰ هنوز آزاد باشد، چون تمدید هم به
آن نیاز دارد.
:::
