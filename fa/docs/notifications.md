# اعلان‌ها

زاگرس می‌تواند از سه راه بگوید چه اتفاقی افتاده: یک رباتِ تلگرام برای ادمین‌ها،
وب‌هوکِ دیسکورد، و وب‌هوکِ HTTPِ امضا‌شده برای سیستم‌های خودتان.

تحویل یک کارِ زمان‌بندی‌شده است (`JOB_SEND_NOTIFICATIONS_INTERVAL`، ۳۰ ثانیه)، پس
هر رخداد حداکثر نیم‌دقیقه بعد می‌رسد.

## تلگرام

| متغیّر | کاربرد |
|---|---|
| `TELEGRAM_API_TOKEN` | توکنِ ربات — بدون آن ربات کاری نمی‌کند |
| `TELEGRAM_LOGGER_CHANNEL_ID` | کانال یا گفتگویی که پیام‌های لاگ را می‌گیرد |
| `TELEGRAM_PROXY_URL` | پروکسی برای فراخوانیِ تلگرام، وقتی خودِ پنل نمی‌تواند مستقیم برسد |

ربات یک ابزارِ **ادمین** است: فقط به ادمین‌های ثبت‌شده در پنل پاسخ می‌دهد
(`/start` و `/help` برای شروع)، و می‌تواند از همان گفتگو کاربران را مدیریت کند —
افزودنِ حجم، افزودنِ زمان، تغییرِ محدودیت‌ها، ویرایشِ یادداشت — از همان مسیرهایی که
داشبورد استفاده می‌کند، پس هیچ کاری از اعتبارسنجی رد نمی‌شود.

## دیسکورد

| متغیّر | کاربرد |
|---|---|
| `DISCORD_WEBHOOK_URL` | وب‌هوکِ سراسریِ پنل برای گزارش‌ها (تغییرِ وضعیت و بقیهٔ رخدادهای پایین) |
| وب‌هوکِ هر ادمین | روی ادمین تنظیم می‌شود — گزارش‌های او هم آنجا می‌رود، کنارِ وب‌هوکِ سراسری |

## وب‌هوک‌های خروجی

نشانی‌ای از سیستمِ خودتان را بدهید تا زاگرس همان رخدادها را آنجا POST کند.

| متغیّر | کاربرد |
|---|---|
| `WEBHOOK_SECRET` | اگر تنظیم شود، هر درخواست آن را در هدرِ `x-webhook-secret` می‌فرستد تا بتوانید مطمئن شوید فرستنده واقعاً پنل است |
| `RECURRENT_NOTIFICATIONS_TIMEOUT` | فاصلهٔ تلاشِ مجدد (پیش‌فرض ۱۸۰ ثانیه) |
| `NUMBER_OF_RECURRENT_NOTIFICATIONS` | چند بار تلاش برای تحویلِ ناموفق (پیش‌فرض ۳) |

::: tip
همیشه `WEBHOOK_SECRET` را تنظیم کنید. نشانی‌ای که به هر POST اعتماد کند، نشانی‌ای
است که هر کسی می‌تواند به آن بنویسد.
:::

## کدام رخدادها اطلاع می‌دهند

| متغیّر | رخداد |
|---|---|
| `NOTIFY_STATUS_CHANGE` | تغییرِ وضعیتِ یک کاربر |
| `NOTIFY_USER_CREATED` | ساختِ کاربر |
| `NOTIFY_USER_UPDATED` | ویرایشِ کاربر |
| `NOTIFY_USER_DELETED` | حذفِ کاربر |
| `NOTIFY_USER_DATA_USED_RESET` | بازنشانیِ مصرفِ کاربر |
| `NOTIFY_USER_SUB_REVOKED` | لغوِ لینکِ اشتراک |
| `NOTIFY_IF_DATA_USAGE_PERCENT_REACHED` | عبور از درصدی از مصرف |
| `NOTIFY_IF_DAYS_LEFT_REACHED` | رسیدن به N روز مانده به انقضا |
| `NOTIFY_LOGIN` | ورودِ یک ادمین |

پیش‌فرضِ همه `True` است؛ برای ساکت‌کردنِ یک رخداد آن را `False` بگذارید.

## یادآورها

کنارِ اعلانِ رخدادها، زاگرس **یادآور** را هم به‌عنوان یک رکوردِ درجه‌یک نگه
می‌دارد: هر یادآور به یک کاربر تعلق دارد، یک نوع دارد (مصرف یا انقضا)، یک آستانهٔ
اختیاری، و می‌تواند خودش منقضی شود. این همان چیزی است که پیامِ «داری تمام
می‌کنی» را می‌فرستد — یک‌بار به‌ازای هر یادآور، نه یک‌بار در هر دقیقه.

## برچسب‌های وضعیت

واژه‌هایی که در اعلان‌ها به‌کار می‌روند قابل تغییرند — اگر کاربرانتان به زبانِ
دیگری می‌خوانند:

`ACTIVE_STATUS_TEXT`، `EXPIRED_STATUS_TEXT`، `LIMITED_STATUS_TEXT`،
`DISABLED_STATUS_TEXT`، `ONHOLD_STATUS_TEXT`.

## وقتی اعلان نمی‌رسد

```bash
sudo zagros logs | grep -i notify
```

دنبالِ خطوطِ تلاشِ مجدد بگردید: سه تلاش با فاصلهٔ سه دقیقه رفتارِ پیش‌فرض است، نه
یک صفِ گیرکرده. اگر وب‌هوک اصلاً نمی‌رسد، بررسی کنید که نشانیِ شما با ۲xx جواب
می‌دهد — هر پاسخِ دیگری «تحویلِ ناموفق» حساب می‌شود.
