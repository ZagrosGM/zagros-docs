# اپلیکیشن‌ها

یک **اپلیکیشن** یک اپ کلاینت رسمی است: بیلد سفارشی‌شده (white-label) از کلاینت
زاگرس که به پنل شما متصل است. صفحهٔ Applications همان‌جایی است که اپ را
می‌سازید، برند می‌کنید، کاربران را به آن متصل می‌کنید و برای هر پلتفرم
خروجیِ قابل‌نصب می‌گیرید — بدون نیاز به محیط توسعهٔ محلی.

## مفاهیم

| مفهوم | معنا |
|---|---|
| اپلیکیشن | یک اپ کلاینتِ برندشده با شناسه، کلیدها، آیکون و بیلدهای خودش |
| Grant | کاربرِ متصل‌شده به اپ؛ فقط کاربرانِ grantشده می‌توانند وارد شوند |
| اعتبار اپ | نام‌کاربری/رمزی که مشترک داخل اپ وارد می‌کند |
| بیلد | یک کار بیلد که به‌ازای هر پلتفرم خروجی می‌سازد |
| Target | یک سه‌تاییِ پلتفرم/معماری/artifact داخل یک بیلد |
| Builder | محل اجرای بیلد: میزبانِ خود پنل (master) یا یک سرور خارجی از راه SSH |

## ساخت اپلیکیشن

در **Applications → New application**:

| فیلد | نکته |
|---|---|
| نام | ۱ تا ۱۲۸ کاراکتر؛ در داشبورد نمایش داده می‌شود و در نام artifactها (slug) اثر می‌گذارد |
| API base URL | محل Client API اپ — معمولاً همان آدرس پنل |
| زبان پیش‌فرض | پیش‌فرض `fa`؛ زبان اولیهٔ UI اپ |

پاسخ (و کارت اپ) **شناسهٔ اپلیکیشن** را نشان می‌دهد (شناسهٔ عمومی به شکل
`2751dadd-…`). آن را در یکپارچه‌سازی‌هایی که از REST API با اپ کار می‌کنند
کپی کنید.

### آیکون

روی کارت اپ یک PNG مربعی (حداکثر ۱ مگابایت) بارگذاری کنید. این آیکون داخل
بیلدهای اندروید به‌عنوان آیکون لانچر جاسازی می‌شود — بدون هیچ کار برندینگ در
سمت بیلد.

### کلیدهای عمومی

هر اپ یک کلید **signing** و یک کلید **config** دارد (هرکدام با kid مثل
`sig-384254b5ee751179`). این‌ها هم‌اکنون عمومی‌اند — کپی‌کردنشان داخل
پیکربندی‌های بیلد بی‌خطر است و برای اعتبارسنجیِ تحویل‌های مهروشده استفاده
می‌شوند؛ نیمهٔ خصوصی هرگز از key store پنل بیرون نمی‌رود.

## کاربران، grant و ورود

اپ تا وقتی کاربران به آن **grant** نشوند کاری نمی‌کند:

* در دیالوگ **Users** دکمهٔ *Issue app credentials* کاربر را متصل می‌کند و
  ورودِ او را می‌سازد.
* اعتبارها شبیه `u16.mgyhjnml` / یک رمز تولیدشده است. رمز فقط **یک‌بار**
  نمایش داده می‌شود — پنل فقط hash آن را نگه می‌دارد.
* خارج‌کردن کاربر از حالت ورودِ اپلیکیشن، دسترسی‌های اپی او را لغو می‌کند؛
  grant دوباره بدون bind جدید دسترسی را برمی‌گرداند.

مشترکِ گم‌کردهٔ رمز اپ دو مسیر خود-خدمتی دارد:

1. دیالوگ **Users** → *Reissue* (سمت ادمین).
2. **صفحهٔ پورتال** — وقتی حالت مؤثرِ کاربر ورود اپلیکیشن است، صفحه دکمهٔ
   *reissue* می‌دهد؛ جفتِ جدید یک‌بار روی کارت سبز نشان داده می‌شود. ورودهای
   قدیمی همان لحظه می‌میرند.

برای اینکه پنل تصمیم می‌گیرد چه کسی داخل اپ وارد شود و چه کسی لینک اشتراک
می‌گیرد، بخش «حالت تحویل» در راهنمای [کاربران](./users.md) را ببینید.

## بیلد اپ

**Trigger build** ویزاردِ بیلد را باز می‌کند.

### سورس و نسخه

| حالت | رفتار |
|---|---|
| **Simple** | آخرین revision ریپوهای مجازِ اپ و SDK را خودکار resolve می‌کند (`POST /api/zagros/builds/resolve-source`). همیشه به‌روز، بدون pin کردن. |
| **Advanced** | خودتان URL و commit دقیقِ هر دو ریپو (اپ و SDK) را pin می‌کنید — بیلدِ بازتولیدپذیر. |

*Version* رشتهٔ نسخهٔ اپ شماست (مثل `1.0.0`). پنل به‌طور خودکار یک
**شمارهٔ بیلد** صعودیِ مخصوص همان اپ هم اختصاص می‌دهد.

### Targets

به‌ازای هر پلتفرم/معماری/artifact یک ردیف:

| پلتفرم | معماری (معمول) | Artifact |
|---|---|---|
| `android` | `arm64-v8a`، `armeabi-v7a`، `x86_64` | `apk`، `aab` |
| `windows` | معماری میزبان | `zip` (باندل exe + DLL) |
| `linux` | `amd64`، `arm64` | `tar.gz` |
| `macos` | معماری میزبان | `tar.gz` |
| `ios` | `arm64` | `ipa` |

ویزارد با تغییر پلتفرم artifact را خودکار عوض می‌کند و ترکیب‌هایی که خط تولید
می‌سازد را غیرفعال می‌کند.

### Build on: داخلی یا خارجی

| گزینه | معنا |
|---|---|
| **Master server** | بیلد روی همان میزبانی که پنل اجرا می‌شود انجام می‌گیرد. ساده‌ترین راه؛ از دیسک/CPU پنل استفاده می‌کند. |
| **External server** | یک میزبان لینوکسِ جدا که با SSH دیده می‌شود. *Test host* اول آن را می‌سنجد (اعتبارِ probe فقط برای همان probe است و هرگز ذخیره نمی‌شود)؛ پیش‌نیازها خودکار نصب می‌شوند. |

هر دو مسیر یک **گارد منابع** دارند: وقتی میزبان حداقلِ حافظه/دیسکِ آزادِ
پیکربندی‌شده را نداشته باشد، بیلد از همان اول رد می‌شود با کد
`resources_insufficient` (کمبود RAM خودکار تا حدود ۴ گیگ swapfile می‌سازد و
بیلد زیر سقف CPU/حافظه اجرا می‌شود). آستانه‌ها و کلید قطع، متغیر محیطیِ
builder هستند (`ZAGROS_GUARD_MIN_MEMORY_MB`، `ZAGROS_GUARD_MIN_DISK_MB`،
`ZAGROS_GUARD_DISABLE=1`).

### اعتبارها (Credentials)

مرحلهٔ *Credentials* ویزارد رازها را به بیلد وصل می‌کند:

* **توکن git خصوصی** — برای بیلد از ریپوهای خصوصی.
* **اعتبار میزبان خارجی** — بعد از probe موفق، در یک گامِ جدا و با تصمیمِ
  صریح ذخیره می‌شود.

اعتبارها فقط **داخل ورکری که بیلد را اجرا می‌کند** رمزگشایی می‌شوند و هرگز در
لاگ‌ها یا باندلِ خروجی ظاهر نمی‌شوند.

### دنبال‌کردن بیلد

لیست بیلد یک ردیف به‌ازای هر کار صف‌شده نشان می‌دهد
(`android/arm64-v8a/apk — …`) با وضعیتش. بازکردنِ یک بیلد وضعیت هر target،
پیشرفت، کد خطا، لاگ‌ها و جدول artifactها (نام، sha256، حجم) را می‌دهد.
داشبورد تا وقتی بیلد از `queued/running` خارج شود polling می‌کند.

## Artifactها و دانلود

| پلتفرم | نام artifact (معمول) |
|---|---|
| android | `{slug}-{arch}.apk` / `{slug}-{arch}.aab` |
| windows | `{slug}-windows-{arch}.zip` |
| linux | `{slug}-linux-{arch}.tar.gz` |
| macos | `{slug}-macos-{arch}.tar.gz` |
| ios | `{slug}.ipa` |

دانلود از دیالوگ جزئیات بیلد، یا مستقیم از API:

```
GET /api/zagros/builds/{build_id}/artifacts/{platform}/{arch}/{filename}
```

هر ردیف artifact یک `sha256` دارد — دانلود را با آن بسنجید.

## سورس‌ها و mirrorها

سورس‌های بیلد **allowlist** دارند (`ZAGROS_BUILD_SOURCE_ALLOWLIST`،
`ZAGROS_BUILD_SDK_ALLOWLIST`). پیش‌فرض‌ها ریپوی رسمی اپ `ZagrosGM/Zagros-VPN`
و SDK هم‌خانوادهٔ آن است. پنل‌های بدون اینترنت معمولاً این‌ها را به mirrorهای
git محلی نشان می‌دهند؛ کشِ resolve پنج دقیقه می‌ماند
(`ZAGROS_BUILD_DEFAULT_SOURCE_JSON` پیش‌فرضِ pin‌شده را نام می‌برد).

## بیلد از REST API

ویزارد همان endpointهایی را صدا می‌زند که یک بات می‌تواند:

| گام | Endpoint |
|---|---|
| ساخت اپلیکیشن | `POST /api/zagros/applications` |
| resolve سورسِ حالت Simple | `POST /api/zagros/builds/resolve-source` |
| probe میزبان خارجی | `POST /api/zagros/builds/external-host-probe` |
| صف‌کردن بیلد | `POST /api/zagros/applications/{id}/builds` |
| poll یک بیلد | `GET /api/zagros/builds/{build_id}` |
| لیست بیلدها | `GET /api/zagros/builds` |
| لغو | `POST /api/zagros/builds/{build_id}/cancel` |
| لاگ / artifact | `GET /api/zagros/builds/{build_id}/logs` · `/artifacts` |
| دانلود artifact | `GET /api/zagros/builds/{build_id}/artifacts/{platform}/{arch}/{filename}` |
| اعتبار بیلد | `POST/GET /api/zagros/build-credentials`، `/rotate`، `/revoke` |
| ورکرهای خارجی | `POST/GET /api/zagros/builder/workers`، `/register-token` |

کمترین بدنه برای یک بیلد:

```bash
curl -fsS -X POST "https://panel.example.com/api/zagros/applications/$APP_ID/builds" \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{
    "version": "1.0.0",
    "source_repo": "https://github.com/ZagrosGM/Zagros-VPN.git",
    "source_revision": "<commit>",
    "sdk_source_repo": "https://github.com/ZagrosGM/Zagros-VPN-SDK.git",
    "sdk_source_revision": "<commit>",
    "targets": [{"platform": "android", "arch": "arm64-v8a", "artifact": "apk"}]
  }'
```

حالت `Advanced` ویزارد دقیقاً همین بدنه است؛ حالت `Simple` چهار فیلد سورس را
از `resolve-source` پر می‌کند.

## وقتی بیلد شکست می‌خورد

| `failure_code` | معنا |
|---|---|
| `resources_insufficient` | میزبان حافظه/دیسکِ آزادِ کافی ندارد (گارد). جا خالی کنید یا آستانه‌ها را بالا ببرید. |
| `provision_failed` / `provision_unsupported` | آماده‌سازی میزبان بیلد شکست خورد / آن پلتفرم آن‌جا پشتیبانی نمی‌شود. |
| `worker_error` | ورکر کار را از راه دور رد کرد (ناهم‌خوانی گارد/allowlist). |

بیلد را باز کنید تا پیام کامل خطا و لاگ‌ها را ببینید؛ ردیفِ کار، targetِ
شکست‌خورده را نام می‌برد.

::: tip
بیلدِ همزمانِ پنج پلتفرم، پنج کار است نه یک کار. فقط پلتفرم‌هایی را صف کنید که
واقعاً منتشر می‌کنید؛ هر target موقع آماده‌شدن مستقل دانلود می‌شود.
:::
