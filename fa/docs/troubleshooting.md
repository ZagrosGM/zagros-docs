# عیب‌یابی

با دو دستوری شروع کنید که همه‌چیز را نگاه می‌کنند:

```bash
sudo zagros doctor      # داکر، دیتابیس، هسته‌ها، پورت‌ها، DNS، رجیستری
sudo zagros status      # سرویس‌ها، ایمیج، سلامت، جدولِ هسته‌ها
sudo zagros logs        # پنل همین لحظه چه می‌گوید
```

## نشانه ← علت ← رفع

| نشانه | علتِ محتمل | چه کنید |
|---|---|---|
| پنل بالا نمی‌آید | پورت اشغال است، یا migration شکست خورده | `zagros logs`، بعد `zagros doctor`؛ `zagros repair` مواردِ رایج را درست می‌کند (پوشه‌ها، env، ایمیج، کانتینر، schema) |
| `503 admin authentication stack unavailable` | پنل هنوز بالا می‌آید، یا پایگاه‌داده در دسترس نیست | صبر کنید تا سالم شود، بعد `zagros doctor`؛ از علت در لاگ نوشته می‌شود نه اینکه قورت داده شود |
| خطا دربارهٔ نبودنِ کلیدِ JWT | migration روی این پایگاه‌داده اجرا نشده | `zagros advanced migrate` |
| نود هرگز جفت نمی‌شود | پورت‌های `62050`/`62051` در دسترس نیستند، توکن قبلاً مصرف شده، یا ایجنت دوباره نصب شده | از پنل در‌دسترس‌بودن را بررسی کنید؛ اگر ایجنت دوباره نصب شده، توکن را **بچرخانید** (قبلی مصرف شده) |
| نود جفت می‌شود ولی چیزی سرو نمی‌دهد | هسته هنوز پیکربندی ندارد، یا فهرستِ اکانت همگرا نشده | تبِ **Cores** نود را باز کنید؛ اکانت‌ها ظرف ۳۰ ثانیه همگرا می‌شوند — `zagros logs \| grep accounts` |
| کانفیگِ کاربرِ جدید وصل نمی‌شود ولی قدیمی‌ها وصل می‌شوند | نود فهرستِ کهنه‌ای سرو می‌کند | ۳۰ ثانیه صبر کنید (جاروب دوباره می‌فرستد)، یا از داشبورد نود را `sync` کنید |
| کاربر روی نود آفلاین است و مصرفی ثبت نمی‌شود | گزارشِ نود نمی‌رسد | از پنل `62050` را بررسی کنید، بعد `DISABLE_RECORDING_NODE_USAGE` در `.env` |
| «آنلاینِ هم‌اکنون» زیاد به‌نظر می‌رسد | فعالیتِ ۹۰ ثانیهٔ اخیر را می‌شمرد، نه «متصل و بیکار» | برای Xray، آنلاین یعنی *شمارنده‌ها نسبت به نمونهٔ قبلی رشد کرده‌اند* — کلاینتِ بیکار آنلاین نیست |
| حضور می‌گوید *نامعلوم* | خواندنِ یک هسته شکست خورده، یا اصلاً APIیِ حضور ندارید | اشتباه نیست: نبودِ مدرک، مدرکِ نبود نیست. `failed_cores` را در `/api/zagros/users/online` ببینید |
| نشانیِ اشتراک در مرورگر لینک می‌دهد | مرورگر شناخته نشدید | هدرِ `Accept: text/html` و یک `User-Agent` مرورگری بفرستید، یا از `?format=` استفاده کنید |
| قالبِ آپلود‌شده نادیده گرفته می‌شود | فایل روی سرور نیست، یا به خطا خورده | `docker compose logs zagros \| grep -i "subscription template"` — قالبِ شکسته همیشه به صفحهٔ داخلی برمی‌گردد |
| صدورِ گواهی شکست می‌خورد | پورتِ ۸۰ اشغال است، یا هیچ کلاینتِ ACME نصب نیست | رابط نامِ تأمین‌کننده‌ای را که پیدا کرده می‌گوید (certbot / acme.sh / lego)؛ پورت ۸۰ را آزاد کنید و دوباره تلاش کنید |
| بعد از به‌روزرسانی پنل ناسالم ماند | باید خودش برگشته باشد | `zagros advanced rollback`، و `zagros logs` را ببینید |

## چیزها کجا هستند

| مسیر | محتوا |
|---|---|
| `/opt/zagros/` | `docker-compose.yml` و `.env` |
| `/var/lib/zagros/` | پایگاه‌داده، هسته‌ها، گواهی‌ها، کلیدها، لاگ‌ها، پشتیبان‌ها |
| `/usr/local/bin/zagros` | خط‌فرمانِ میزبان |

## تست مثلِ خودِ کلاینت

```bash
# آنچه یک کلاینت می‌بیند
curl -s -A "v2rayNG/1.8" https://panel.example.com/sub/TOKEN

# آنچه مرورگر می‌بیند
curl -s -A "Mozilla/5.0 Chrome/120" -H "Accept: text/html" \
     https://panel.example.com/sub/TOKEN

# آیا ترافیک واقعاً از نود بیرون می‌رود؟
curl --socks5 127.0.0.1:1080 https://api.ipify.org
```

آخری باید IPِ **نود** را چاپ کند. اگر IPِ پنل را چاپ کرد، کاربر اصلاً از نود عبور
نمی‌کند.

## وقتی باید عمیق‌تر بروید

```bash
sudo zagros shell                 # داخلِ کانتینرِ پنل
sudo zagros advanced sync         # اعمالِ دوبارهٔ همهٔ اکانت‌ها روی هسته‌ها
sudo zagros doctor --json | jq .  # گزارشِ کاملِ ماشین‌خوان
```

::: tip
`zagros repair` را به ویرایشِ دستی ترجیح دهید: فقط تغییراتی می‌دهد که بتواند
توجیهشان کند (پوشه‌ها، env، ایمیج، کانتینر، schema) و می‌گوید چه کرده.
:::
