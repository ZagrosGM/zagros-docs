# کاربران

هر کاربر یک اشتراک است: یک لینک، یک سهمیه، یک انقضا و یک حساب روی هر هسته‌ای که
به او داده شده است.

## ساخت کاربر

| فیلد | نکته |
|---|---|
| نام کاربری | ۳ تا ۳۲ کاراکتر: حرف، عدد، `_`، `-`، `@`، `.` |
| پروکسی / inbound | پروتکل‌ها و tagهای مجاز کاربر |
| سقف حجم | کل بایت‌ها یا نامحدود |
| انقضا | تاریخ یا بدون انقضا |
| سقف IP | بیشینهٔ IP مبدأ همزمان در همهٔ هسته‌ها (`0` یعنی نامحدود) |
| سقف دستگاه / HWID | بیشینهٔ شناسه‌های پایدار مجاز برای دریافت اشتراک (`0` یعنی نامحدود) |
| وضعیت | پیش‌فرض `active`؛ هنگام ساخت `on_hold` نیز پذیرفته می‌شود |

**قالب‌ها** مجموعهٔ reusable از inboundها و محدودیت‌ها را نگه می‌دارند.

## وضعیت‌ها

| وضعیت | معنا | تعیین‌کننده |
|---|---|---|
| `active` | سرویس عادی | شما |
| `disabled` | دستی خاموش | شما |
| `on_hold` | ساخته شده ولی هنوز شروع نشده/متوقف | شما |
| `limited` | پایان سهمیهٔ ترافیک | زاگرس |
| `expired` | عبور از تاریخ انقضا | زاگرس |

عبور IP از سقف، وضعیت را عوض نمی‌کند و کل حساب را تعلیق نمی‌کند؛ فقط جدیدترین IP
اضافه موقتاً مسدود می‌شود.

## سقف IP

`ip_limit` مشاهده‌های IP مبدأ احراز‌شده را از همهٔ هسته‌های محلی و نودهای بومی
paired اجتماع می‌کند. با سقف `1`، اولین آدرس فعال متصل می‌ماند و آدرس دومِ
جدیدتر روی تمام inboundهای مدیریت‌شدهٔ VPN مسدود و اتصال‌های فعالش قطع می‌شود.
فاصلهٔ بررسی پیش‌فرض ۵ ثانیه و ban پیش‌فرض ۱۵ دقیقه است و در
**Settings → Security** تغییر می‌کند. پس از پایان زمان خودکار آزاد می‌شود.

Firewall فقط درگاه‌های VPN را هدف می‌گیرد؛ HTTP داشبورد و اشتراک باز می‌ماند.
NAT ممکن است چند دستگاه را یک IP نشان دهد و reverse proxy پنهان‌کنندهٔ مبدأ
شمارش درست را ناممکن می‌کند.

## سقف دستگاه / HWID

`device_limit` مستقل از IP آنلاین، دریافت اشتراک را کنترل می‌کند. مقدار مثبت
هدر `X-Device-ID` یا `X-HWID` را روی درخواست اشتراک و تحویل Client API رسمی
اجباری می‌کند. اولین N شناسه ثبت می‌شوند و شناسهٔ تازه HTTP 403 می‌گیرد. IP و
User-Agent هرگز شناسهٔ دستگاه فرض نمی‌شوند.

ویرایشگر کاربر نمایش کوتاه دستگاه‌های ثبت‌شده را نشان می‌دهد و مدیر می‌تواند
یکی یا همه را پاک کند. فقط digest کلیددار ذخیره می‌شود، نه ID خام.

این سیاست secretی را که قبلاً export و دستی کپی شده پس نمی‌گیرد؛ تحویل‌های بعدی
اشتراک/config را محدود می‌کند.

## مصرف و حضور

مصرف همهٔ هسته‌ها و نودها به یک سهمیهٔ کاربر اعمال می‌شود. کاربر وقتی آنلاین است
که دست‌کم یک هسته یا نود سشن زنده گزارش کند. هستهٔ IP-blind می‌تواند حضور را ثابت
کند ولی آدرس ساختگی به `ip_limit` نمی‌دهد. شکست خواندن یک هسته یعنی حضور نامعلوم،
نه آفلاین.

## لینک اشتراک

هر کاربر یک لینک دارد و لغو، توکن را فوراً می‌چرخاند. مسیرهای چندبخشی مانند
`sub/test` پشتیبانی می‌شوند. وقتی سقف دستگاه فعال است، کلاینت دریافت‌کننده باید
هدر شناسهٔ پایدارش را بفرستد.

[معنای دقیق API](./api.md#معنای-سقف-ip) را ببینید.

## حذف خودکار

`USERS_AUTODELETE_DAYS` حذف چند روز پس از انقضا را تنظیم می‌کند (`-1` غیرفعال).
حذف دائمی است؛ پیش از فعال‌سازی پشتیبان بگیرید.
