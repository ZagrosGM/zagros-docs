# هسته‌ها

یک **هسته** یک موتورِ پروتکل با درایورِ خودش است. زاگرس هفت هسته دارد:

| هسته | مادّه‌ای که معمولاً تولید می‌کند |
|---|---|
| `xray` | VLESS، VMess، Trojan، Shadowsocks |
| `singbox` | Hysteria2، TUIC و مجموعهٔ پروتکل‌های sing-box |
| `openvpn` | فایل‌های `.ovpn` |
| `wireguard` | فایل‌های `.conf` و QR |
| `ssh` | اکانت‌های SSH |
| `softether` | SoftEther VPN |
| `pptp` | PPTP/L2TP (با نسخهٔ پین‌شدهٔ accel-ppp) |

پنل هیچ جای دیگری فهرستی از پروتکل‌ها را hard-code نکرده: درگاه‌ها، قالب‌ها،
قالب‌های اشتراک و داشبورد همگی همان چیزی را می‌خوانند که درایورها اعلام می‌کنند.

## توانمندی‌ها

درایورها اعلام می‌کنند چه می‌توانند بکنند و رابط همان را نشان می‌دهد — کنترلی که
به‌کار نمی‌آید نمایش داده نمی‌شود، و فراخوانیِ عملیاتی که پشتیبانی نمی‌شود به‌جای
شکستِ دیرهنگام، یک خطای نوع‌دار می‌دهد.

| توانمندی | معنا |
|---|---|
| `USER_MANAGEMENT` | ساخت/به‌روزرسانی/حذفِ اکانت |
| `SUSPEND_RESUME` | تعلیقِ ارزان بدونِ ساختِ دوباره |
| `USAGE_ACCOUNTING` | شمارندهٔ ترافیکِ هر اکانت |
| `ONLINE_TRACKING` | سشن‌های زنده / دستگاه‌های آنلاین |
| `HOT_RELOAD` | اعمالِ پیکربندی بدونِ ری‌استارتِ کامل |
| `SERVICE_CONTROL` | راه‌اندازی/توقف با پنل |

## نصب و اجرا

از میزبان:

```bash
sudo zagros cores                        # چه نصب است و وضعیتش چیست
sudo zagros cores install singbox
sudo zagros cores reload wireguard
sudo zagros cores uninstall pptp --purge
```

یا در داشبورد زیرِ **Cores**: نصب، راه‌اندازی، توقف، بازخوانی، لاگِ زنده و
تنظیمات.

## تغییرِ نسخه

هر هسته‌ای که درایورش نسخه‌ها را از مخزنِ بالادستیِ خودش کشف می‌کند، می‌تواند به
**یک نسخهٔ منتشرشده — بالاتر یا پایین‌تر — یا به تگی که خودتان می‌نویسید** پین شود.
نسخهٔ نصب‌شده در فهرست علامت می‌خورد و اعمالِ تغییر تنظیمات، داده‌ها و اکانت‌ها را
نگه می‌دارد.

```bash
sudo zagros cores update xray --version v26.6.1
```

هسته‌هایی که سیستم‌عامل نصب می‌کند (نه پنل) در رابط دلیلش را می‌گویند، نه یک
انتخاب‌گرِ خالی.

## درگاه‌ها (Inbound)

هسته‌ها **درگاه** دارند — نقطه‌های ورودِ نام‌دار (یک پورت با پروتکل و تنظیمات).
کاربران به درگاه‌ها نسبت داده می‌شوند و مادّهٔ اشتراک از همین درگاه‌ها ساخته
می‌شود.

* کاتالوگِ درگاه‌ها بین پنل و همهٔ نودها یکسان است، پس یک نام همه‌جا یک معنا دارد.
* میزبان‌ها (نشانی‌هایی که کانفیگ به آن‌ها اشاره می‌کند) برای هر درگاه مدیریت
  می‌شوند؛ افزودنِ نود می‌تواند نشانی‌اش را خودکار به‌عنوان میزبان بیفزاید.
* یک درگاه را می‌توان بدونِ حذف غیرفعال کرد، پس توقفِ ترافیک پیکربندی را خراب
  نمی‌کند.

## هسته‌ها کجا اجرا می‌شوند

| مکان | مدیریت از | نکته |
|---|---|---|
| میزبانِ پنل | تبِ **Cores** | هسته‌های خودِ مستر |
| یک نود | نود ← تبِ **Cores** | چیدمانِ یکسان؛ پیکربندی با همگام‌سازی |

کارتِ هستهٔ نود عمداً دکمهٔ *settings* یا *update* جداگانه ندارد: نود با
همگام‌سازی پیکربندی می‌شود، نه دستی.

## سلامت

بررسیِ سلامتِ هسته هر ۱۰ ثانیه اجرا می‌شود. هسته‌ای که مرده گزارش (و در صورتِ
امن‌بودن دوباره راه‌اندازی) می‌شود، و هسته‌ای که degrade شده روی کارتش می‌گوید به‌جای
اینکه وانمود کند سالم است. هسته‌ای که بالا نمی‌آید لاگش را در همان کارت نشان
می‌دهد — بدون نیاز به SSH.

::: tip
اگر لینکِ کاربری کار نمی‌کند در حالی که پنل می‌گوید همه‌چیز خوب است، اول وضعیتِ
خودِ هسته را ببینید: *در حال اجرا* با *در حال سرویس‌دهی* یکی نیست، و هسته‌ای که
نمی‌تواند به پورتش متصل شود همین را در کارت گزارش می‌کند.
:::
